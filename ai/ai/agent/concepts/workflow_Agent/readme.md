WorkFlow 本质上是一套预定义的流程，可以把它想象成一套生产的流水线。每一步都有明确的输入和输出。每一个节点的逻辑是固定的。当条件满足，就会进入下一个环节。
在技术上，它通常变成一个编排好的AI工作流引擎
一个由AI调用，条件判断，循环逻辑组成的一个图谱。

langchain 是用于快速搭建工作流的开发框架，灵活构建各类智能任务链路。

## 思考
AI 工作流（invoke）也能干活，它和Agent（React） 有什么区别？
很多人会混淆，反正都是AI 在执行任务。

## Agent 智能体
和workflow 逻辑完全不一样，它不走在一条预设的轨道上，而是站在一个开放的空间里，自己去探索怎么去做（智能）。从技术角度，一个Agent 往往具有三大核心能力：

第一个能力 ： 感知环境 
通过输入文本、图像、数据来理解任务，有哪些工具可以调用，当前情况如何，如何分步骤、如何规划。

第二个能力 ： 规划路径
不是预先定义好的，而是动态去生成任务链。

第三个能力 ： 执行行动
去调用工具，完成子任务，并不断去调整。

## 举例
你让Agent 去规划旅行，他可能先去搜一下机票和酒店价格，再去查天气和签证需求，然后结合你的偏好和预算，动态去权衡方案。
整个过程，它可能走的路径和你的预期的完全不同，这就是Agent 的关键区别，自主性和适应性。它不会被一个固定的流程限制，而是像一个思考中的个体。所以，本质的区别在于：workflow是确定性的执行，Agent 是一个不确定的探索。 workflow 就好像一条高速公路，路线很清晰很固定，效率很高，但能到达既定的终点。
Agent 更像一个司机，它知道要去哪，但可以随时去改道（修路，感知环境），尝试新的路线，甚至在目的地发生变化的时候，自行调整

所以，从产业角度， workflow 更适合流程化，重复性的任务。
比如审核流程、数据清洗、客服AI
Agent 更适合动态的一个角色场景。
比如：复杂的搜索、策略规划。

从技术栈的领域，workflow 更依赖于规则，图形化编排（coze），流程引擎。
Agent 更依赖于大模型的推理能力和记忆能力，包括它的工具调用等。

未来我们的AI工程中将会集合Agent 和 workflow的双重能力。
底层是workflow 去提供稳定性和可控性。上层是Agent 去提供智能性和灵活性。

workflow 是骨架，Agent 是workflow的大脑
workflow 没什么创造力，Agent 有，但不可控，不可预测，一起结合，即高效又有智慧
