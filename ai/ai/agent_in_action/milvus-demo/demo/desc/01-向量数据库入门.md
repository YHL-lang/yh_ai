## 1. 🤔 为什么传统数据库不够用了？

我们熟悉的 MySQL、PostgreSQL 是**关系型数据库**，擅长的是**精确匹配**：

```sql
SELECT * FROM articles WHERE title = '三体';
```

它能精准找出 `title` 等于 `三体` 的行。但现实里我们更常问的是这种「模糊」问题：

> ❓「有没有讲**中国科幻**的小说？」  
> ❓「和『三体』**风格相似**的书有哪些？」  
> ❓「这张图片里的人是**谁**？」

这些问题没法用 `=` 或 `LIKE '%关键词%'` 来回答，因为它们要的不是「字符串相等」，而是**「语义相似」**。

而**语义相似**这个需求，本质上是要比较**向量之间的距离**。这就引出了下一个问题——

---

## 2. 🧮 什么是向量？什么是 Embedding？

**向量（Vector）就是一串有序的数字**。比如：

```
"你好"  --Embedding模型-->  [0.12, -0.34, 0.56, 0.08, ...]   # 768 个数字
```

这个过程叫 **Embedding（嵌入）**：把文字、图片、声音这些「非结构化数据」变成一串**固定长度的数字**。

它的神奇之处在于：**语义越接近的东西，向量在空间里的位置就越近**。

```
        "猫"    [0.9, 0.1, ...]
          ↑ 距离近
        "小猫"  [0.8, 0.2, ...]
              ↓ 距离远
        "汽车"  [0.1, 0.9, ...]
```

于是，「找相似」这个模糊问题，就被转化成了一个**明确的数学问题**：**计算两个向量之间的距离/相似度**。

> ⚠️ 关键点：向量是**高维**的。真实模型产出的向量动辄 **768、1024、1536 维**，而不是上面画的 2 维。维度高，就导致「挨个比」慢到没法用——这正是第 4 节要解决的问题。

---

## 3. 📚 向量数据库的核心概念（对照 MySQL）

向量数据库就是**专门存储和检索高维向量**的数据库。Milvus 是最主流的开源向量数据库之一。

> 🧠 记不住概念？先记住一句话：**向量数据库 ≈ MySQL 换了个擅长存向量、算相似度的内核**。

| 向量数据库（Milvus） | 关系型数据库（MySQL） | 说明 |
|---|---|---|
| **Collection** 集合 | **Table** 表 | 存数据的地方，一个集合一类数据 |
| **Field** 字段 | **Column** 列 | 集合里的一列，比如向量列、文本列 |
| **Vector 向量字段** | （无对应物） | 专门存高维向量的列 |
| **Dimension** 维度 | （无对应物） | 向量有多少个数字，建集合时就要定好 |
| **Index** 索引 | **Index** 索引 | 让查询变快 |
| **MetricType** 相似度度量 | （无对应物） | 用哪种方式算「像不像」 |

在代码里，建集合的维度就是先定好的：

```js
const DIMENSION = 4; // 维度：这个向量有 4 个数字
```

> ⚠️ 维度是**建集合时固定**的，后面插进去的每条向量都必须正好是 4 个数字，多了少了都会报错。

---

## 4. 🗂️ 为什么需要索引？（字典和图书馆的类比）

没有索引时，每次查询都要把库里的向量和查询向量**逐一算相似度**，复杂度是 **O(n)**：

> 数据量一大，就慢得没法用。

**索引就是用来「迅速缩小查询范围」的**。两个绝妙的类比：

### 📖 类比一：字典

翻字典查一个字，你不会从第一页挨个翻到最后，而是用**拼音、偏旁**做索引，直接跳到对应区域。

### 🏛️ 类比二：图书馆找《三体》

- ❌ **没有索引**：每本书都要翻一下，全馆扫一遍
- ✅ **有索引**：`文学馆 → 小说区 → 科幻书架`，三步直达

索引就是把数据先**归类/分簇**好，查询时只在小范围里比，而不是全量比。

Milvus 里有一种叫 **IVF_FLAT** 的**聚簇索引**，原理就是：先把向量聚成若干簇，查询时只找最近的几个簇，**毫秒级**出结果。

> 💡 真实开发里，直接上 Milvus 的 `AUTOINDEX`（自动索引）即可，它会根据数据量自动选最优方案，本系列就用它。

---

## 5. 🔧 相似度度量：MetricType

「像不像」有好几种算法，Milvus 里常见的三种：

| 类型 | 中文名 | 适用场景 |
|---|---|---|
| `COSINE` | 余弦相似度 | 看**方向**像不像，文本语义检索最常用 |
| `L2` | 欧氏距离 | 看**距离**近不近，图片检索常用 |
| `IP` | 内积 | 数值越大越相似 |

本系列用 `COSINE`（算文本语义的默认首选）。

## 7. 🔌 第一步：连接 Zilliz Cloud

先把客户端和需要的类型引进来，再建立连接：

```js
import {
  MilvusClient,   // 客户端，用来连接 Zilliz（Milvus 云）
  IndexType,      // 索引类型
  MetricType      // 相似度计算类型
} from '@zilliz/milvus2-sdk-node'
import 'dotenv/config'

const ADDRESS = process.env.MILVUS_ADDRESS; // 云端地址
const TOKEN   = process.env.MILVUS_TOKEN;   // API Key

const client = new MilvusClient({
  address: ADDRESS,
  token: TOKEN
});
```

> 💡 `import 'dotenv/config'` 会在启动时自动把 `.env` 加载进 `process.env`，所以 `process.env.MILVUS_ADDRESS` 才能取到值。

连接成功后，用 `checkHealth()` 确认集群健康：

```js
const checkHealth = await client.checkHealth();
if (!checkHealth.isHealthy) {
  console.error('连接失败', checkHealth.reasons);
  process.exit(1);
}
console.log('✅ 链接成功，集群状态正常。');
```

> 🩺 `checkHealth()` 返回 `{ isHealthy, reasons }`：健康时 `isHealthy` 为 `true`；不健康时 `reasons` 里会有原因。

---

## 8. 📦 第二步：创建集合（Collection）

> 🧠 回忆：**Collection 就是向量数据库里的「表」**。

```js
const COLLECTION_NAME = 'test';
const DIMENSION = 4; // 向量维度：每个向量 4 个数字

await client.createCollection({
  collection_name: COLLECTION_NAME,
  dimension: DIMENSION,
  auto_id: true   // 主键 id 自动生成，不用自己传
});
console.log('✅ 集合创建成功');
```

> ⚠️ 集合**只需创建一次**。重复创建同名集合会报错，所以真实代码里建议先判断是否存在：

```js
const exist = await client.hasCollection({ collection_name: COLLECTION_NAME });
if (!exist.value) {
  await client.createCollection({ collection_name: COLLECTION_NAME, dimension: DIMENSION, auto_id: true });
}
```

---

## 9. 🗂️ 第三步：创建索引（Index）

> 🧠 回忆第 4 节：**索引就是让查询从 O(n) 变成毫秒级的「字典/图书馆分类」**。

```js
await client.createIndex({
  collection_name: COLLECTION_NAME,
  field_name: 'vector',            // 给哪个字段建索引（向量字段默认叫 vector）
  index_type: IndexType.AUTOINDEX, // 自动索引，交给 Milvus 选最优方案
  metric_type: MetricType.COSINE   // 用余弦相似度算「像不像」
});
console.log('✅ 索引创建成功');
```

---

## 10. ➕ 第四步：插入数据（Insert）

> 🧠 回忆：向量数据库存的是**高维向量**。插入时给每条数据一个向量 + 其他字段。

```js
const data = [
  { vector: [0.1, 0.2, 0.3, 0.4], content: '这是第一条数据' },
  { vector: [0.5, 0.6, 0.7, 0.8], content: '这是第二条数据' }
];

const insertRes = await client.insert({
  collection_name: COLLECTION_NAME,
  data   // 直接传 JSON 数组，不用写 SQL
});
console.log('✅ 插入成功', insertRes.IDs);
```

> 💡 两点和 MySQL 很不一样的地方，特别有意思：
>
> 1. **不用写 SQL**——传个 JSON 数组就完事，太简单了；
> 2. **更宽松**——甚至可以在插入数据时**顺便带上新字段**（比如这里的 `content`），不需要像 MySQL 那样先 `ALTER TABLE` 加列。这是因为 Milvus 集合默认开启了**动态字段（Dynamic Field）**。

## 11. 🧩 完整代码（把上面拼起来）

把 7–10 节拼成一个 `main.mjs`，就是完整可运行的脚本：

```js
import {
  MilvusClient,
  IndexType,
  MetricType
} from '@zilliz/milvus2-sdk-node'
import 'dotenv/config'

const ADDRESS = process.env.MILVUS_ADDRESS;
const TOKEN   = process.env.MILVUS_TOKEN;

async function main() {
  const client = new MilvusClient({ address: ADDRESS, token: TOKEN });
  console.log('正在连接 Zilliz Cloud....');

  const checkHealth = await client.checkHealth();
  if (!checkHealth.isHealthy) {
    console.error('连接失败', checkHealth.reasons);
    return;
  }
  console.log('✅ 链接成功，集群状态正常。');

  const COLLECTION_NAME = 'test';
  const DIMENSION = 4;

  // 集合只需建一次：先判断是否存在
  const exist = await client.hasCollection({ collection_name: COLLECTION_NAME });
  if (!exist.value) {
    await client.createCollection({
      collection_name: COLLECTION_NAME,
      dimension: DIMENSION,
      auto_id: true
    });
    console.log('✅ 集合创建成功');

    await client.createIndex({
      collection_name: COLLECTION_NAME,
      field_name: 'vector',
      index_type: IndexType.AUTOINDEX,
      metric_type: MetricType.COSINE
    });
    console.log('✅ 索引创建成功');
  }

  const data = [
    { vector: [0.1, 0.2, 0.3, 0.4], content: '这是第一条数据' },
    { vector: [0.5, 0.6, 0.7, 0.8], content: '这是第二条数据' }
  ];

  const insertRes = await client.insert({
    collection_name: COLLECTION_NAME,
    data
  });
  console.log('✅ 插入成功', insertRes.IDs);
}

main().catch(console.error);
```

运行：

```bash
node src/main.mjs
```
