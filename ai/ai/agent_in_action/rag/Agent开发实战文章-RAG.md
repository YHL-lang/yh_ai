## 一、LLM 的幻觉问题

### 🤥 什么是幻觉？

大模型知道的知识，取决于训练时给它的**数据集**。如果你问它：

> "我们公司内部新上线的 XX 系统怎么用？"
> "2026 年世界杯预选赛最新战况是什么？"

LLM 的回答会发生什么？

```
❌ 幻觉场景：
   用户："我们公司内部系统怎么登录？"
   LLM："请访问 https://xxx.com，使用工号和密码登录……"
        （编造了一个不存在的 URL 和流程）

   用户："最近的行业法规有哪些更新？"
   LLM："根据2026年发布的《XX法》第3条规定……"
        （法条不存在，完全是编的）
```

> 🎯 核心矛盾：LLM 的知识截止于训练数据的时间点，且它**不会说"我不知道"**——它会用非常确信的语气编造答案。这就是**幻觉（Hallucination）**。

### 💡 解决思路

| 方案 | 成本 | 适用场景 |
|------|------|----------|
| 🔬 **微调（Fine-tune）** | 💰💰💰 高 | 大公司、专业领域、需要大量算力 |
| 📚 **RAG（检索增强）** | 💰 低 | ✅ 绝大多数场景——先查资料再回答 |

> 🎯 用户要查询的内容，我们先去内部**知识库**里查一下，把相关文档作为背景知识放到 Prompt 里再给大模型。大模型通过这些文档知道了背景，就可以基于事实回答——**这就是 RAG 的核心思想**。

## 二、RAG 是什么

### 🧠 核心定义

**RAG = Retrieval（检索）+ Augmented（增强）+ Generation（生成）**

```
用户提问："光光和东东怎么成为朋友的？"
         │
         ▼
┌────────────────────────────┐
│  📚 Retrieval 检索          │
│  去知识库里搜索相关文档片段  │
│  → 找到：chapter 3, 4 的片段 │
└────────────────────────────┘
         │
         ▼
┌────────────────────────────┐
│  📝 Augmented 增强          │
│  把检索到的文档拼到 Prompt 里│
│  "根据以下资料回答问题：     │
│   [文档片段1] [文档片段2]    │
│   问题：光光和东东怎么……"   │
└────────────────────────────┘
         │
         ▼
┌────────────────────────────┐
│  🤖 Generation 生成         │
│  LLM 基于增强后的 Prompt    │
│  生成基于事实的回答         │
│  "光光和东东从幼儿园就认识   │
│   了，他们……"              │
└────────────────────────────┘
```

> 🎯 三步走：**查资料 → 拼到 Prompt → 让 LLM 回答**。LLM 没有变聪明，但 Prompt 里的上下文变丰富了。

## 三、向量 Embedding：语义搜索的核心

### 🔍 关键词搜索的局限

用户问"怎么成为朋友"，知识库里有"从幼儿园就认识了"——关键词匹配找不到，因为词面不重合。

### 📐 向量语义搜索

把文本转成**多维向量**来表达语义。相似的语义 → 向量之间夹角小：

```
维度示例：
  食用性  0 = 无  ——  1 = 高
  硬度    0 = 液体  ——  1 = 硬

  水果  [0.9, 0.3]   ──┐  语义相近，夹角小
  苹果  [0.9, 0.5]   ──┤
  香蕉  [0.9, 0.1]   ──┘
  石头  [0.1, 0.9]   ← 方向完全不同！

  通过余弦相似度计算：
  水果 vs 苹果  →  夹角很小  →  高度相关 ✅
  水果 vs 石头  →  夹角很大  →  不相关 ❌
```

> 💡 真实的 Embedding 模型用几百到上千维向量，能表达非常丰富的语义。"怎么成为朋友" 和 "从幼儿园就认识了" 在向量空间中距离很近。

### 🏗️ 嵌入模型（Embedding Model）

| 特性 | 生成模型（Generation Model） | 嵌入模型（Embedding Model） |
|------|---------------------------|---------------------------|
| 用途 | 生成文本 | 把文本转成向量 |
| 输出 | 一段话 | 一组数字 `[0.12, -0.34, ...]` |
| 价格 | 💰💰 贵 | 💰 便宜 |
| 代表 | GPT-4, DeepSeek | `text-embedding-3-small` |

> 🎯 文本、图片、PDF、语音——都可以通过 Embedding 向量化后进行语义搜索。

## 四、Document 切分：构建知识库

### 📄 为什么需要切分？

一整本书塞进 Prompt 不现实（token 有限 + 成本高）。需要把知识库的文档按**自然语义单元**切分成小块（段落、章节、页）。

### 📝 代码：用 `Document` 构建知识片段

```javascript
import { ChatOpenAI, OpenAIEmbeddings } from '@langchain/openai';
// txt, js, pdf 切成 段落 一定的大小来切
// 文档 Document
import { Document } from '@langchain/core/documents';

// 生成模型 —— 负责回答问题
const model = new ChatOpenAI({
  temperature: 0,
  model: process.env.MODEL_NAME,
  apiKey: process.env.OPENAI_API_KEY,
  configuration: {
    baseURL: process.env.OPENAI_BASE_URL,
  }
})

// 嵌入模型 —— 负责把文本转成向量
const embeddings = new OpenAIEmbeddings({
  apiKey: process.env.OPENAI_API_KEY,
  model: process.env.EMBEDDINGS_MODEL_NAME,
  configuration: {
    baseURL: process.env.OPENAI_BASE_URL,
  }
})
```

> 💡 两个模型各司其职：`ChatOpenAI` 负责生成回答（贵），`OpenAIEmbeddings` 负责向量化（便宜）。

### 📝 构建 Document 数组

```javascript
const documents = [
  new Document({
    pageContent: `光光是一个活泼开朗的小男孩，他有一双明亮的大眼睛，总是带着灿烂的笑容。光光最喜欢的事情就是和朋友们一起玩耍，他特别擅长踢足球，每次在球场上奔跑时，就像一道阳光一样充满活力。`,
    // metadata 用于后续过滤或溯源，不参与向量化计算，但非常有用
    metadata: {
      chapter: 1,
      character: "光光",
      type: "角色介绍",
      mood: "活泼"
    },
  }),
  new Document({
    pageContent: `东东是光光最好的朋友，他是一个安静而聪明的男孩。东东喜欢读书和画画，他的画总是充满了想象力。虽然性格不同，但东东和光光从幼儿园就认识了，他们一起度过了无数个快乐的时光。`,
    metadata: {
      chapter: 2,
      character: "东东",
      type: "角色介绍",
      mood: "温馨"
    },
  }),
  // ... 共 7 个 Document，涵盖完整故事线
];
```

| 字段 | 用途 |
|------|------|
| `pageContent` | 文档正文，会被 Embedding 向量化，参与语义搜索 |
| `metadata` | 附加信息（章节、角色、类型、情绪），**不参与向量计算**，但可用于过滤和溯源 |

> 🎯 **metadata 很关键**：搜索时不参与匹配，但找到结果后可以告诉用户"这段信息来自第 3 章，类型是友情情节"——这就是**可溯源（Attribution）**。

### 📊 本课的知识库：一个完整故事

这 7 个 Document 构成了一个儿童故事的知识库：

| 章节 | 内容 | type | mood |
|------|------|------|------|
| ch1 | 光光角色介绍 | 角色介绍 | 活泼 |
| ch2 | 东东角色介绍 | 角色介绍 | 温馨 |
| ch3 | 光光邀请东东踢球 | 友情情节 | 鼓励 |
| ch4 | 一起练习，互帮互助 | 友情情节 | 互助 |
| ch5 | 比赛获胜，友谊加深 | 高潮转折 | 激动 |
| ch6 | 好朋友互相学习 | 结局 | 欢乐 |
| ch7 | 多年后，友谊永存 | 尾声 | 温馨 |

## 五、RAG 完整架构

### 🏗️ 两阶段流程

```
═══════════════════════ 离线阶段：构建知识库 ═══════════════════════

  📄 原始文档（txt/pdf/网页）
         │
         ▼
  ✂️ 切分（按章节/段落/固定大小）
         │
         ▼
  📐 Embedding（每个片段转成向量）
         │
         ▼
  🗄️ 向量数据库（持久化存储向量 + 原文）
     如：FAISS、Chroma、Pinecone、Milvus

═══════════════════════ 在线阶段：检索 + 增强 + 生成 ═══════════════════════

  👤 用户提问："光光和东东怎么成为朋友的？"
         │
         ▼
  📐 Embedding（把问题也转成向量）
         │
         ▼
  🔍 相似度检索（去向量数据库查最相近的片段）
         │
         ▼
  📝 拼接 Prompt：
     "根据以下资料回答问题：
      [片段1] 东东和光光从幼儿园就认识了...
      [片段2] 光光每天放学后教东东踢足球...
      问题：光光和东东怎么成为朋友的？"
         │
         ▼
  🤖 LLM 生成 → "光光和东东从幼儿园就认识了，通过一起踢足球加深了友谊……"
```

### 🔑 为什么向量数据库是必须的？

| 方案 | 问题 |
|------|------|
| MySQL / PostgreSQL | 做不到向量相似度搜索 |
| 内存数组 | 存得多会爆，进程重启数据丢失 |
| **向量数据库** | ✅ 专用索引（ANN 近似最近邻）+ 持久化存储 |

### 📝 RAG Agent 工作流代码骨架

```javascript
const questions = [
  "光光和东东怎么成为朋友的？",
]

// 完整的 RAG Agent 流程：
// 1. 把 documents 里的每个 pageContent 用 embeddings 向量化
// 2. 存入向量数据库（如 FAISS、Chroma）
// 3. 用户提问时，把问题也向量化
// 4. 在向量数据库中检索最相似的 top-K 个文档片段
// 5. 把检索到的片段作为背景知识拼到 Prompt 里
// 6. LLM 基于增强后的 Prompt 生成回答
```

## 六、本课学习总结

### 🧠 知识点

```
📋 RAG 检索增强生成 · 知识点
│
├── 🤥 LLM 幻觉
│   ├── 知识截止于训练数据时间点
│   ├── 不会说"不知道"，会编造答案
│   └── 企业内部文档 / 最新资讯 LLM 不知道
│
├── 💡 解决方案
│   ├── 微调 Fine-tune：成本高、需要算力
│   └── RAG：成本低、先查资料再回答 ✅
│
├── 🧠 RAG = Retrieval + Augmented + Generation
│   ├── ① Retrieval 检索：去知识库找相关文档
│   ├── ② Augmented 增强：拼到 Prompt 里
│   └── ③ Generation 生成：LLM 基于事实回答
│
├── 📐 Embedding 嵌入
│   ├── 把文本转成多维向量表达语义
│   ├── 语义越接近 → 向量夹角越小
│   ├── 余弦相似度计算相关性
│   ├── 嵌入模型 ≠ 生成模型（更便宜）
│   └── 支持文本/图片/PDF/语音
│
├── 📄 Document 构建
│   ├── pageContent：文档正文（参与向量化）
│   ├── metadata：附加信息（过滤 + 溯源）
│   ├── 切分粒度：按章节/段落/大小
│   └── 不参与向量计算但非常有用
│
├── 🏗️ RAG 两阶段
│   ├── 离线：切分 → Embedding → 向量数据库
│   └── 在线：提问向量化 → 相似度检索 → 拼接Prompt → LLM生成
│
└── 🗄️ 向量数据库
    ├── 传统数据库做不到向量相似度搜索
    ├── ANN 近似最近邻索引
    └── FAISS / Chroma / Pinecone / Milvus
```

### ✅ 知识清单

| 编号 | 掌握项 | 核心要点 |
|------|--------|----------|
| 1 | LLM 幻觉 | LLM 不知道的事情会编造，不会说"我不知道" |
| 2 | RAG 定义 | Retrieval（检索）+ Augmented（增强）+ Generation（生成） |
| 3 | Embedding 嵌入 | 把文本转成向量，语义越接近向量夹角越小 |
| 4 | 余弦相似度 | 向量夹角的余弦值，衡量语义相关性 |
| 5 | 嵌入模型 vs 生成模型 | embedding model 转向量（便宜），generation model 生成文本（贵） |
| 6 | `Document` 结构 | `pageContent`（正文，参与向量化）+ `metadata`（附加信息，用于过滤溯源） |
| 7 | 文档切分 | 按章节/段落/固定大小切成自然语义单元 |
| 8 | 向量数据库 | 专用数据库存储向量，支持相似度检索 |
| 9 | RAG 离线阶段 | 切分文档 → Embedding → 存入向量数据库 |
| 10 | RAG 在线阶段 | 问题向量化 → 相似度检索 → 拼到 Prompt → LLM 生成 |

### 📊 Agent 能力全景

| 维度 | 前七课 | RAG |
|------|--------|-----|
| 解决的问题 | LLM **能做什么**（Tool、Loop、CLI、MCP） | LLM **知道什么**（消除幻觉） |
| 核心机制 | Tool 调用 + ReAct 循环 | 检索知识库 + 增强 Prompt + 生成回答 |
| 引入的新模型 | 无（只用 ChatOpenAI） | **Embedding Model**（嵌入模型） |
| 引入的新存储 | 无 | **向量数据库**（FAISS/Chroma 等） |
| 关键数据 | Tool 调用结果 | **Document（pageContent + metadata）** |

> 🎯 **RAG 的定位**：前七课解决 Agent 的"动手能力"——调用工具、执行命令、操控浏览器。RAG 解决 Agent 的"知识储备"——让 LLM 在回答之前先去知识库查资料，基于事实回答而不是凭空编造。两者结合，Agent 既能做事又能知道该怎么做。
