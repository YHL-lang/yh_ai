# 🚀 快速排序（Quick Sort）详解

> 快速排序是一种基于**分治策略**的高效排序算法，平均时间复杂度为 **O(n log n)**，是应用最广泛的排序算法之一。

## 1. 核心思想

快速排序的核心可以用一句话概括：

> 🎯 **选一个基准值（pivot），比它小的放左边，比它大的放右边，然后对左右两边递归地做同样的事。**

```
           ┌─────────┐
           │  pivot  │
           │  (基准)  │
           └────┬────┘
                │
     ┌──────────┼──────────┐
     ▼          ▼          ▼
 ┌───────┐  ┌───────┐  ┌───────┐
 │ < pivot│  │ pivot │  │ > pivot│
 │ 左子数组│  │ 已就位 │  │ 右子数组│
 └───┬───┘  └───────┘  └───┬───┘
     │                      │
     ▼                      ▼
  递归排序               递归排序
```

## 2. 算法步骤概览

快速排序遵循 **分 → 治 → 合** 三部曲：

```
┌──────────────────────────────────────────────────────────┐
│                      快速排序 三部曲                       │
├──────────┬──────────────────┬──────────────────────────────┤
│   分     │       治         │            合                │
│ (Divide) │   (Conquer)     │         (Combine)            │
├──────────┼──────────────────┼──────────────────────────────┤
│ 选取基准 │ 将子数组排序     │ 因为原地排序，数组已有序      │
│ 划分数组 │ （递归调用自身） │ 无需显式合并                  │
└──────────┴──────────────────┴──────────────────────────────┘
```

## 3. 代码逐段详解

### 3.1 整体结构

```javascript
function quickSort(nums, left, right) {
  if (left >= right) return;          // 递归终止条件
  let pivot = partition(nums, left, right); // ① 分：划分数组
  quickSort(nums, left, pivot - 1);   // ② 治：排序左半部分
  quickSort(nums, pivot + 1, right);  // ② 治：排序右半部分
  return nums;                        // ③ 合：原地排序，直接返回
}
```

| 参数 | 含义 |
|------|------|
| `nums` | 待排序数组 |
| `left` | 当前处理区间的左边界 |
| `right` | 当前处理区间的右边界 |
| `pivot` | 本轮结束后基准值所在的**索引位置** |

> 💡 **关键理解**：`pivot` 是基准值经过本轮 partition 后的**最终位置**，这个位置在后续递归中不会再改变——该元素已经"就位"。

---

### 3.2 核心函数：`partition`（划分）

这是整个算法的**灵魂**。它负责将数组划分为"左小右大"的两部分。

```javascript
function partition(nums, left, right) {
  let i = left, j = right;  // 🏷️ 左右双指针

  while (i < j) {           // 当两指针未相遇时，持续扫描

    // ── 右指针 j：从右往左找第一个小于基准值的元素 ──
    while (i < j && nums[j] >= nums[left]) {
      j--;  // 比基准值大或相等的，本就在右边，跳过
    }

    // ── 左指针 i：从左往右找第一个大于基准值的元素 ──
    while (i < j && nums[i] <= nums[left]) {
      i++;  // 比基准值小或相等的，本就在左边，跳过
    }

    // ── 交换这两个"站错队"的元素 ──
    [nums[i], nums[j]] = [nums[j], nums[i]];
  }

  // 🎯 将基准值放到两子数组的分界线上
  [nums[left], nums[i]] = [nums[i], nums[left]];
  return i;  // 返回基准值的最终索引
}
```

#### 📊 双指针扫描示意图

```
基准值 pivot = nums[left] = 2

初始状态:
         left                          right
          │                             │
          ▼                             ▼
        ┌───┬───┬───┬───┬───┬───┐
        │ 2 │ 4 │ 1 │ 0 │ 3 │ 5 │
        └───┴───┴───┴───┴───┴───┘
          ▲                       ▲
          │                       │
          i                       j

Step 1: j 左移，找 <2 的元素
        找到 nums[3] = 0  <  2 ✓ → j 停在索引 3

Step 2: i 右移，找 >2 的元素
        找到 nums[1] = 4  >  2 ✓ → i 停在索引 1

Step 3: 交换 nums[i] 和 nums[j]
        ┌───┬───┬───┬───┬───┬───┐
        │ 2 │ 0 │ 1 │ 4 │ 3 │ 5 │  交换 4 ↔ 0
        └───┴───┴───┴───┴───┴───┘
              ▲       ▲
              │       │
              i       j

Step 4: 继续扫描...
        j 左移 → 找到 nums[2]=1 <2，j 停在 2
        i 右移 → 找到 nums[2]=1，i 停在 2
        i === j，外层循环结束 ✓

Step 5: 基准值归位
        交换 nums[left] 和 nums[i]
        ┌───┬───┬───┬───┬───┬───┐
        │ 1 │ 0 │ 2 │ 4 │ 3 │ 5 │  基准 2 已就位！
        └───┴───┴───┴───┴───┴───┘
                  ▲
                  │
               pivot=2

结果:  左边 [1, 0] 都 < 2  ✓
       右边 [4, 3, 5] 都 > 2  ✓
```

---

### 3.3 为什么先移动右指针？

注意代码中**先移动 `j`（右指针），再移动 `i`（左指针）**，这个顺序很重要！

```javascript
while (i < j && nums[j] >= nums[left]) { j--; }  // ← 先右
while (i < j && nums[i] <= nums[left]) { i++; }  // ← 后左
```

> ⚠️ 如果反过来先移动 `i`，最后交换基准值时可能会把一个大于基准值的元素换到最左边，导致划分出错。**先移动右指针能保证循环结束时 `i` 指向的元素 ≤ 基准值**，交换后才符合"左小右大"。

## 4. 完整执行过程模拟

以输入数组 `[2, 4, 1, 0, 3, 5]` 为例：

```
                        quickSort([2,4,1,0,3,5], 0, 5)
                                  │
                                  ▼
                    ┌─────────────────────────┐
                    │ partition(0,5)           │
                    │ 基准=2, 返回 pivot=2     │
                    │ 数组 → [1,0,2,4,3,5]    │
                    └───────────┬─────────────┘
                                │
                ┌───────────────┼───────────────┐
                ▼                               ▼
    quickSort([1,0,2,4,3,5], 0, 1)    quickSort([1,0,2,4,3,5], 3, 5)
                │                               │
                ▼                               ▼
    ┌─────────────────────┐        ┌─────────────────────┐
    │ partition(0,1)      │        │ partition(3,5)      │
    │ 基准=1, pivot=1     │        │ 基准=4, pivot=4     │
    │ → [0,1,2,4,3,5]    │        │ → [0,1,2,3,4,5]    │
    └─────────┬───────────┘        └─────────┬───────────┘
              │                              │
      ┌───────┼───────┐              ┌───────┼───────┐
      ▼       ▼       ▼              ▼       ▼       ▼
  (0,0)   (2,1)   终止         (3,3)    (5,5)   终止
  终止    终止                 终止     终止

✅ 最终结果: [0, 1, 2, 3, 4, 5]
```

### 递归树可视化

```
                              [2,4,1,0,3,5]
                              pivot=2
                             /          \
                      [1,0]            [4,3,5]
                      pivot=1          pivot=4
                     /      \         /       \
                  [0]       []      [3]       [5]
                   ✅        ✅       ✅        ✅

        📐 递归深度: O(log n)  → 这就是快排高效的原因！
```

## 5. 时间复杂度分析

| 情况 | 时间复杂度 | 原因 |
|------|-----------|------|
| 🟢 **最好/平均** | **O(n log n)** | 每次 pivot 都大约在中间，递归树平衡 |
| 🔴 **最差** | **O(n²)** | 每次 pivot 都是极值（如已排序数组），递归退化为链表 |
| 🟡 **空间复杂度** | **O(log n)** | 递归调用栈的深度 |

### 快排高效的两个关键

```
快排为什么快？   ┌─── pivot 基准值机制
                │    → 每次划分，pivot 的位置就永久确定了
                │    → 递归树的深度是 O(log n)
                │
                └─── 原地交换 + 双指针
                     → 不需要额外开辟数组空间
                     → 每层遍历的开销是 O(n)
```

```
总复杂度 = 递归层数 × 每层工作量

        O(log n)  ×  O(n)  =  O(n log n)  ✅
```

## 6. 稳定性分析

> 🔴 **快速排序是不稳定的排序算法。**

### 为什么不稳定？

看这个例子：数组中有两个相等的元素 `4` 和 `4'`

```
原始数组:  [4, 4', 1, ...]
            ↑   ↑
          基准 相等元素

partition 过程中，双指针交换可能改变相等元素的相对顺序：

  交换前: [4, 4', 1, 0]
  交换后: [0, 4', 1, 4]
               ↑      ↑
            4' 跑到了 4 前面！

❌ 相等元素（4 和 4'）的相对位置颠倒了
```

> 📝 在 `readme.md` 中也特别提到："**相等元素相对位置颠倒，完美体现快排不稳定**"。

## 7. 分治 vs 递归

这是两个容易混淆但本质不同的概念：

| 维度 | 🔁 递归 | 🧩 分治 |
|------|--------|--------|
| **是什么** | 代码实现方式 | 算法设计思想 |
| **特征** | 函数调用自身 | 分 → 治 → 合 三步 |
| **方向** | 自顶向下，缩小问题规模 | 自顶向下拆分，自底向上合并 |
| **关系** | 是实现手段 | 是方法论 |

```
┌─────────────────────────────────────────────────┐
│                  分治策略                        │
│  ┌─────────┐    ┌──────────┐    ┌─────────┐    │
│  │  分     │ →  │   治     │ →  │   合    │    │
│  │ Divide  │    │ Conquer  │    │ Combine │    │
│  │拆成子问题│    │递归求解  │    │合并结果 │    │
│  └─────────┘    └──────────┘    └─────────┘    │
│                       │                         │
│                       ▼                         │
│              绝大多数用递归实现                   │
│              function 调用自身                   │
└─────────────────────────────────────────────────┘
```

> 🎯 **结论**：递归是"怎么写代码"，分治是"怎么想问题"。快排用递归来实现分治思想。

## 8. 与其他排序算法对比

| 算法 | 平均时间 | 最差时间 | 空间 | 稳定 | 核心策略 |
|------|---------|---------|------|------|---------|
| 🫧 冒泡排序 | O(n²) | O(n²) | O(1) | ✅ 稳定 | 相邻两两比较交换 |
| 🎯 选择排序 | O(n²) | O(n²) | O(1) | ❌ 不稳定 | 每轮选最小的放前面 |
| 📥 插入排序 | O(n²) | O(n²) | O(1) | ✅ 稳定 | 当前元素往前找位置插入 |
| 🚀 **快速排序** | **O(n log n)** | O(n²) | O(log n) | ❌ 不稳定 | 分治 + 双指针基准划分 |
