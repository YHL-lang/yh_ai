# 🔁 递归算法：从入门到实践

## 一、什么是递归

> 💡 **递归**（Recursion）是指在函数的定义中调用函数自身的方法。

想象你站在一面镜子前，镜子里有镜子里的镜子……无限反射。递归也是如此——函数在执行过程中调用自身，每一层都在解决一个**更小规模**的相同问题，直到问题小到可以直接求解。

```
┌─────────────────────────────────┐
│          递归的哲学              │
│                                 │
│   大问题 ──拆解──▶ 子问题       │
│      ▲               │         │
│      │               ▼         │
│   合并结果 ◀─── 解决子问题      │
│                                 │
│   "把大象装进冰箱"的思路：       │
│   1. 打开冰箱门                 │
│   2. 把大象装进去（递归关键！）  │
│   3. 关上冰箱门                 │
└─────────────────────────────────┘
```

## 二、从累加问题入门

### 🎯 问题描述

> 求 `1 + 2 + 3 + ... + n` 的和。

这是一个非常经典的问题，我们分别用两种方式来解决它。

### 🔹 方式一：迭代（循环）

最直观的思路：用一个 `for` 循环从 1 累加到 n。

```js
function sum(n) {
    let total = 0;
    for (let i = 1; i <= n; i++) {
        total += i;
    }
    return total;
}

console.log(sum(100)); // 5050
```

- ✅ 简单直接，一眼就能看懂
- ✅ 不占用额外的调用栈空间
- ❌ 没有体现问题的结构特征

### 🔹 方式二：递归（自顶向下）

换一个角度思考：`sum(5)` 其实就是 `5 + sum(4)`，而 `sum(4)` 又是 `4 + sum(3)`……一直推到 `sum(1) = 1`。

这种**自顶向下**的思维可以用一棵树来表示：

```
        sum(5)
       = 5 + sum(4)
              = 4 + sum(3)
                     = 3 + sum(2)
                            = 2 + sum(1)
                                   = 1   ← 终止！
```

用代码表达这个思想：

```js
function sum(n) {
    if (n === 1) {
        return 1;            // 🛑 终止条件
    }
    return n + sum(n - 1);   // 🔁 递归调用
}

console.log(sum(100)); // 5050
```

> 🧠 **关键直觉**：我们不需要关心 `sum(n-1)` 是怎么算出来的——**相信它能正确返回结果**，然后在此基础上加上 `n` 即可。这就是递归的"信任跳跃"（Leap of Faith）。

## 三、递归三要素

每个正确的递归函数都必须具备以下三个要素：

| 要素 | 说明 | 在累加问题中的体现 |
|------|------|-------------------|
| 🛑 **终止条件**（Base Case） | 问题小到可以直接求解，不再递归 | `n === 1` 时返回 `1` |
| 📐 **递归公式**（Recurrence） | 大问题与小问题之间的关系 | `f(n) = f(n-1) + n` |
| 🔁 **相同的子问题** | 每一层解决的是**同构**的子问题 | `sum(n-1)` 和 `sum(n)` 结构一致 |

缺少任何一个，递归要么死循环，要么逻辑错误：

```js
// ❌ 缺少终止条件 → 无限递归，栈溢出！
function badSum(n) {
    return n + badSum(n - 1); // RangeError: Maximum call stack size exceeded
}
```

## 四、数组扁平化实战

### 🎯 问题描述

> 将嵌套的多维数组"拍平"成一维数组。

```
输入:  [1, [2, [3, 4, [5, 6]]]]
输出:  [1, 2, 3, 4, 5, 6]
```

### 🔹 方式一：ES6 原生 `flat()` 方法

最简单的方式是使用 JavaScript 内置的 `Array.prototype.flat()`：

```js
const arr = [1, [2, [3, 4, [5, 6]]]];

// Infinity 表示无限层级的扁平化
console.log(arr.flat(Infinity));
// 输出: [1, 2, 3, 4, 5, 6]
```

| 参数 | 含义 |
|------|------|
| `flat()` | 默认只扁平化 **1 层** |
| `flat(2)` | 扁平化 **2 层** |
| `flat(Infinity)` | 扁平化 **所有层级** |

- ✅ 一行代码搞定
- ❌ 面试官不会只让你写这个 😅
- ❌ 面试常考点：**手写递归实现**

### 🔹 方式二：手写递归实现

理解了递归三要素，扁平化问题迎刃而解：

> 对数组的每一项：
> - 如果是**数字** → 直接放入结果
> - 如果是**数组** → 递归地拍平它，再合并进结果

```js
const flatten = (arr) => {
    let res = [];
    arr.forEach((item) => {
        if (Array.isArray(item)) {
            // 🔁 子数组 → 递归拍平
            res = res.concat(flatten(item));
        } else {
            // 🛑 非数组 → 直接放入结果
            res.push(item);
        }
    });
    return res;
};

const arr = [1, 2, [3, 4, [5, 6]]];
console.log(flatten(arr));
// 输出: [1, 2, 3, 4, 5, 6]
```

### 🧩 执行过程图解

```
flatten([1, [2, [3, 4]]])
│
├─ 1 不是数组 → res = [1]
│
├─ [2, [3, 4]] 是数组 → flatten([2, [3, 4]])
│   │
│   ├─ 2 不是数组 → res = [2]
│   │
│   ├─ [3, 4] 是数组 → flatten([3, 4])
│   │   │
│   │   ├─ 3 不是数组 → res = [3]
│   │   ├─ 4 不是数组 → res = [3, 4]
│   │   └─ 返回 [3, 4]
│   │
│   └─ 返回 [2, 3, 4]
│
└─ 最终返回 [1, 2, 3, 4]
```

### 🔹 进阶：支持自定义深度的扁平化

仿照 `flat(depth)` 的设计，我们可以给它加上深度控制：

```js
const flatten = (arr, depth = 1) => {
    let res = [];
    arr.forEach((item) => {
        if (Array.isArray(item) && depth > 0) {
            // 每深入一层，depth 减 1
            res = res.concat(flatten(item, depth - 1));
        } else {
            res.push(item);
        }
    });
    return res;
};

const arr = [1, [2, [3, [4, 5]]]];

console.log(flatten(arr, 1));    // [1, 2, [3, [4, 5]]]  只拍平1层
console.log(flatten(arr, 2));    // [1, 2, 3, [4, 5]]     拍平2层
console.log(flatten(arr, Infinity)); // [1, 2, 3, 4, 5]   全部拍平
```

### 🔹 进阶：用 `reduce` 更优雅地实现

```js
const flatten = (arr) =>
    arr.reduce(
        (acc, item) =>
            acc.concat(Array.isArray(item) ? flatten(item) : item),
        []
    );

console.log(flatten([1, [2, [3, 4, [5, 6]]]]));
// 输出: [1, 2, 3, 4, 5, 6]
```

## 五、递归 vs 迭代

| 维度 | 迭代（循环） | 递归 |
|------|------------|------|
| 🧠 **思维方式** | 自底向上，一步步算 | 自顶向下，大问题拆小问题 |
| 📖 **可读性** | 简单问题直观 | 天然匹配"分治"结构 |
| 💾 **内存开销** | O(1) 额外空间 | O(n) 调用栈空间 |
| ⚡ **性能** | 通常更快 | 有函数调用开销 |
| 🌲 **适用场景** | 线性结构 | 树 / 图 / 嵌套结构 |

> 🎯 **选择标准**：如果问题的结构本身就是**树状或嵌套**的（如 DOM 遍历、文件目录、扁平化），递归几乎是自然选择。如果是简单线性累加，迭代更高效——但递归是理解"分治"思想的绝佳入口。

## 六、总结

> ✨ **递归的本质不是"自己调用自己"，而是把一个问题归约为更小的同类问题。**

| 核心要点 | 说明 |
|---------|------|
| 🛑 **终止条件** | 问题足够小，直接返回答案 |
| 📐 **递归公式** | `f(n)` 与 `f(n-1)` 的关系 |
| 🔁 **相同子问题** | 每一步解决的是结构一致的问题 |
| 🤝 **信任跳跃** | 相信递归调用能正确返回结果 |
